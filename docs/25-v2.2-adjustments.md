# V2.2 迭代记录（界面反馈四条）

> 触发：业务用户在 V2.0 UAT 期间提出的四条界面反馈。
> 性质：`v2.0` 之后的小版本迭代 —— **不改业务状态机、不动任何业务表结构**，
> 只调整交互可读性、补一个入口、并把「单据打印版面」从硬编码变成可配置。
> 验证基线：`pytest` 305 passed；前端 Playwright E2E 全量通过
> （新增 `web/tests/e2e/10-v2.2-ui.spec.ts` 6 条，逐条对应用户反馈）。

## 2. 需求①：操作列可读性与对齐

**问题**（两个独立成因，都是 Element Plus 默认值导致的）：

1. **字太淡**：表格里的行内动作是 `el-button link type="primary"`，文字色直接取
   `--el-color-primary`（`#409eff`）。白底对比度只有 **3.02:1**，在 `size="small"`
   的 12px 字号下明显发虚。
2. **「更多」掉行**：`el-dropdown` 的根元素自带 `vertical-align: top`，而相邻
   `el-button` 是 `middle`；同时 `.el-button + .el-button` 的间距规则**不匹配**
   `el-dropdown`。结果「更多」既贴不上前一个按钮，又错位到下一行。

**做法**：

- `style.css` 只对 **表格内** 的 link 按钮换深色变体（不影响页面级按钮）：
  primary `#1f6fdc`（4.80:1）、success `#3d7f40`（4.97:1）、warning `#96682a`（4.99:1）、
  danger `#c0392b`（5.46:1），并加 `font-weight: 500`；
- 新增 `.row-actions` 容器（`inline-flex` + `gap: 8px` + `nowrap`），
  把行内按钮与 `el-dropdown` 一起收进去，并抵消 Element Plus 的相邻按钮 margin；
- 操作列宽度 320 → 340px（最多 7 个动作时仍不换行）。

**回归保护**：E2E 断言「查看」与「更多」的**垂直中心相差 < 3px**，
且「查看」的计算色等于 `rgb(31, 111, 220)`。

## 3. 需求②：供货商可点击 + 简称必填

### 3.1 可点击，弹只读档案

- 新增 `SupplierDetailDialog`（只读，`ref.open(supplierId)` 打开）：
  显示简称、编码、全称、等级、账期、联系人、电话、税号、开户行、银行账号、供货范围、地址、备注；
- 入口覆盖：
  - 单据**列表**的往来单位列（供应商方向）→ 按钮；
  - 单据**详情抽屉**的「供应商」行 → 按钮；
  - **采购申请单**的「建议供应商」下拉右侧「供货商详情」按钮；
  - **采购单**的「供应商」下拉右侧「供货商详情」按钮；
- `supplier_id` 缺失时（历史单据只有名称快照）**保持纯文本** —— 不做点了没反应的假按钮；
- 无 `master.supplier.view` 权限时弹窗给出明确提示，而不是空白（403 单独文案）。

### 3.2 默认显示简称

- 弹窗标题：`供货商详情 · {简称}`；首行大字是简称，全称作为次要说明跟在后面；
- 采购单/采购申请单的供应商下拉：**选项主文字为简称**，全称作为次要说明补在后面
  （避免两家简称相近时选错）；选中后输入框显示简称；
- 下拉搜索关键词同时匹配 `name` / `code` / `short_name`
  （原先只匹配前两者，会出现"看得见却搜不到"）；
- **存量档案没有简称时**一律回退显示全称，不会出现空标题；
- **删除「建议供应商快照」**（UAT 反馈）：它在表单上只是一次只读回显——下拉本身已经显示简称，
  该字段既不落库、也不参与保存逻辑，真正的"快照"应是保存时固化的名称文本（如采购单的
  `supplier_name`），名不副实；其"点击看详情"的价值已由下拉右侧的「供货商详情」按钮覆盖。
  后端 `suggest_supplier_id` 字段保留不变（列表与详情抽屉仍按 ID 反查名称显示）。

### 3.3 简称必填（BR-V2.2-01）

- 前端：`供应商信息` 档案的「简称」字段标记必填，并在列表列序与表单字段顺序上都提到
  名称之后（业务上先认简称）；
- 后端（真正的边界）：`master_service`
  - **新增**供应商缺简称 → `422 供货商简称不能为空`；
  - **修改**时提交了空的 `short_name` → `422`；未提交该字段则保持原值；
  - 长度上限 64 字；
  - **只作用于供应商** —— 客户的往来习惯是全称，简称仍选填；
- 存量兼容：
  - `migrate_service.claim_party_draft` 认领历史合同草案时用历史名称兜底补简称
    （认领是"存量补录"，不能因为缺简称卡住迁移）；
  - 已有档案不会被自动改写（`db_migrate` 不加修正脚本）。

## 4. 需求③：库存明细「商品类型-物料名称」

`BalanceView` 的结存列表原先「物料名称」「商品类型」是相邻两列，看一行要横向跳两次
才能确认"这是什么料"。现改为**一列**：

```text
物料名称 = `${product_type_name}-${product_name}`    // 类型为空时只显示名称
```

- 类型前缀用 `--ctms-text-secondary` 弱化，视线仍先落到物料名称上；
- 列宽由 150 提到 220，`商品类型` 筛选框保留不变（筛选能力不减）。

## 5. 需求④：打印模板

### 5.1 现状与目标

打印 HTML 原先由 `print_service.py` **硬编码**标题、字段顺序与列清单：改个标题、
把"仓库"挪到表头第一格、把签字栏的"领料/收货"改成"领用人"，都得改代码发版。
现在版面成为**按单据类型保存的配置**，管理员在「系统管理 → 打印模板」自己调。

### 5.2 可配置项

| 分组 | 内容 |
|---|---|
| 文字信息 | 单据标题、副标题、是否附打印时间、页脚文字 |
| 组件位置 | 四个**区块**的整体顺序：标题区 / 表头信息 / 行项明细 / 签字与备注 |
| 表头信息 | 每行字段数（1/2/3）；每个字段的显示开关、**先后顺序**、标签文字、是否独占整行 |
| 行项明细 | 每一列的显示开关、**先后顺序**、列名文字 |
| 签字与备注 | 签字栏文字（可增删、排序，最多 8 项）、审批信息 / 备注 / 作废说明开关 |

### 5.3 实现要点

- **存储**：新表 `print_templates`（`kind` 唯一 + `config` JSON 文本 + 修改人/时间）。
  用 JSON 而不是逐字段建列 —— 模板是排版数据、字段集合会随单据类型演进，
  加列的迁移成本远高于收益（见 `db_migrate.py` 的 SQLite 限制说明）。
  **不改动任何业务表**。
- **默认值即代码**：`print_template_service.default_config(kind)` 由目录常量生成，
  与改造前的硬编码版面**逐项一致**（含盘点单换列、签字栏换名）。库里没有记录时直接用默认值，
  不需要管理员先"初始化模板"。
- **读取即合并**：`get_config()` 把库里的与默认值合并，模板缺项自动回落默认，不会 KeyError。
- **写入即归一**：未知字段/列 key 丢弃、非法表头列数回落、签字栏为空回落默认、
  行项列全被关掉时至少恢复一列 —— 模板坏了会打印不出来，不能让前端随便写库。
  提交的列表**即为最终顺序与可见性**（列表里没有 = 使用者移除了它）。
- **字段自适应**：单据上没有的字段（如采购单没有"入库类型"）渲染时自动跳过，
  不会印出一行"—"。
- **预览**：`POST .../{kind}/preview` 用**提交的（尚未保存的）配置**渲染一张内置样例单据，
  前端把返回的 HTML 写进 `iframe.srcdoc`，编辑后 700ms 去抖自动刷新。
  预览不读业务数据、不落库。

### 5.4 权限与菜单

- 新增权限点：`system.print.view`（menu）、`system.print.edit`（button）；
- 菜单：「资料库 → 打印模板」（`/system/print-templates`）；
- **升级路径修复**：权限点是代码常量，而角色-权限关系落库 —— 新增权限点后已部署库里的
  `sysadmin` 不会自动拥有它（表现为"功能上线了，管理员却 403 / 菜单里看不到"）。
  现在 `init_db.seed_auth` 每次启动都会给 `sysadmin` **补齐**缺失的权限点（只做加法，
  其余内置角色不动，避免覆盖管理员的手工调整）。

## 6. 升级与回滚

**升级**（无需人工 SQL）：

1. 停后端 → 拉取代码 → 启动后端（`create_all` 自动建 `print_templates` 表；
   `seed_auth` 自动给 `sysadmin` 补两个新权限点）；
2. 前端重新构建（`cd web && npm run build`）或让开发服务器热更新；
3. 管理员重新登录（权限点在登录/`auth/me` 时下发），即可在「资料库 → 打印模板」看到入口。

**回滚**：业务表未改动，`print_templates` 是新增表。回退代码后该表被忽略，
打印回到硬编码版面。删除该表即可彻底清理。

**已知取舍**：

- 除 `sysadmin` 外的内置角色**不会自动获得**新权限点。若要把打印模板给采购主管等角色，
  用角色管理页手工勾选，或显式执行 `sync_builtin_roles`（会重置内置角色权限为预设）；
- 模板按**单据类型**共享，不做"按用户/按组织"的多套模板（当前 3~4 人使用场景无此需要）。
