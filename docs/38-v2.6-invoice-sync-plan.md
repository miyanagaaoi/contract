# 38. V2.6 开发计划：发票同步与发票管理改造

> 需求来源：`docs/2.6prompt .txt`
> 前置讨论结论（2026-10-15 已确认）：
> 1. **同步路线 A（内嵌浏览器自动化）**：账号密码写入配置文件读取；发起同步时自动登录电子发票服务平台，平台下发短信验证码时暂停等待人工输入；完成一次登录后会话**保活 1 小时**，期间再次同步免登录；
> 2. **收票进度按价税合计**（采购单金额默认含税，与 V2.5 `total_amount`「进度口径」一致）；
> 3. **同步 = 已认证**（`auth_status` 直接置 `authenticated`）；绑定采购单后的「已确认」是独立状态（未确认 → 已确认）。

## 1. 版本目标

1. 发票管理页面改造：列表展示同步到的所有发票，字段与排序按新口径调整；
2. 发票同步：通过正规账号登录电子发票服务平台（数电票全量发票查询），拉取时间段内取得的进项发票，存库并记录同步时间；手动点击触发；
3. 采购单「更多 → 登记进项发票」改为**弹窗选择一张或多张发票**（默认筛选未确认），绑定后状态变更为已确认，收票进度按发票价税合计自动累计；
4. （顺带）销项侧对称能力不纳入本版，字段与状态设计预留方向扩展。

## 2. 数据模型变更

### 2.1 `Invoice` 表新增列（`app/models_doc.py`）

| 列 | 类型 | 说明 |
|---|---|---|
| `sync_source` | `String(16)` NULL | 同步来源：`tax_platform`（电子发票服务平台）/ NULL=手工录入 |
| `synced_at` | `DateTime` NULL | 最近一次同步时间（列表展示） |
| `bind_status` | `String(16)` NOT NULL DEFAULT `unbound` | `unbound`（未确认）/ `bound`（已确认，绑定采购单后变更） |
| `our_company_id` | `Integer` NULL FK 我方公司 | 签约公司（同步时按纳税人识别号自动匹配系统设置里的我方公司） |
| `seller_name` / `seller_tax_no` | `String` NULL | 开票单位（销方）名称/识别号 |
| `buyer_name` / `buyer_tax_no` | `String` NULL | 收款单位×（见 §3 口径）——收票方（购方）名称/识别号 |

> 兼容：`party_id/party_name`（V2.5 手工口径=供应商）保留不动，同步发票两方向都落 `seller_*`/`buyer_*`，进项发票的 `party` 由 `seller` 派生。

### 2.2 新增 `InvoiceSyncLog` 表

| 列 | 说明 |
|---|---|
| `id`, `started_at`, `finished_at` | 同步起止时间 |
| `date_from`, `date_to` | 拉取区间 |
| `tax_no`（登录账号对应纳税人识别号） | 同步主体 |
| `status` | `running` / `waiting_sms` / `success` / `failed` |
| `fetched` / `inserted` / `skipped_duplicate` | 拉取条数 / 新增 / 重复跳过（按 `invoice_direction + invoice_no` 幂等） |
| `message` | 失败原因 / 说明 |

### 2.3 状态口径（本版冻结）

- `auth_status`：同步进来自动置 **`authenticated`（已认证）**；手工录入仍默认 `pending`，由财务手工认证；
- `bind_status`：`unbound`（未确认）→ 绑定采购单后 `bound`（已确认）；解绑/作废发票回到 `unbound`；
- 列表"状态"列展示：已认证（绿）/ 待认证（灰）× 确认状态徽标（已确认/未确认）。

## 3. 字段口径（同步映射，依据 browser-sessions 抓取样例）

平台"全量发票查询"返回 15 列（`发票明细_91149900MAECLDF33U.xlsx`），映射：

| 平台字段 | 系统字段 | 备注 |
|---|---|---|
| 数电发票号码 | `invoice_no` | 唯一约束幂等键（数电票无发票代码，`invoice_code` 存 `--` 转空） |
| 票种 | `invoice_type` | 数电票（增值税专用发票）/ 数电票（普通发票） |
| 开票日期 | `invoice_date` | 取日期部分；列表默认按此倒序，可切换排序 |
| 金额 | `amount` | 不含税 |
| 税额 | `tax_amount` | |
| 价税合计 | `total_amount` | **收票进度累计口径** |
| 税率 | `tax_rate` | 列表新增列 = 税额/金额×100（平台不直接返回，换算保留 2 位） |
| 购/销方名称 + 查询类型 | `seller_*` / `buyer_*` | 查询类型=「取得发票」（进项）：对方=开票单位（销方），我方=收票方；「开具发票」（销项，本版不拉取） |
| 发票状态 | 过滤条件 | 仅同步「正常」状态 |
| 风险等级/开票人/发票来源 | 不入库 | 列表不展示（如需排查可看 sync log message） |

> 需求中"往来单位变为**开票单位**和**收款单位**"口径确认：进项发票的销方=开票单位；"收款单位"理解为**收票方（我方/购方）**，即页面上两列分别为"开票单位（对方）"与"收票单位（我方）"。若你本意为销项的收款方，讨论时提出修正。

## 4. 同步服务设计（路线 A）

### 4.1 技术选型

- 后端 `playwright`（Python 版，加入 `app/requirements.txt`），`chromium` headless；
- 登录态持久化：`app/data/tax_session/`（storage_state 文件 + 时间戳），**保活 1 小时**：每次成功同步刷新时间戳，超时即删会话，下次同步重新走登录；
- 凭据：**多公司按我方主体码预充**（2026-10-15 业务确认：公司一 `ZC`、公司二 `YX`），
  `CTMS_TAX_SYNC_<主体码>_USERNAME / _PASSWORD / _TAX_NO`（见 `.env.example`），
  密码支持 base64 混淆存储；主体码必须是系统设置「我方公司」字典内的有效值；
  每家公司登录会话按主体码隔离保活（`state_ZC.json` / `state_YX.json`，各 1 小时）。

### 4.2 同步流程（时序）

```
用户点「同步发票」→ 选择日期区间（默认上次同步日 ~ 今天）
  → POST /api/finance/invoices/sync        创建 SyncLog(running)，返回 task_id
  → 后台任务：
      ① 有 1h 内有效会话 → 跳到 ④
      ② 打开登录页，自动填账号密码 → 平台要求短信验证码
         状态置 waiting_sms → 前端弹窗提示"请输入手机验证码"
      ③ 用户输入 → POST /sync/{task_id}/sms → 后端继续提交
         登录成功 → storage_state 落盘（时间戳=now）
      ④ 进入全量发票查询页，设日期区间 + 查询类型=取得发票 + 状态=正常
      ⑤ 逐页抓取（复用 jsanalysis 的接口/表格口径）→ 解析字段
      ⑥ 逐条 upsert：invoice_no 已存在则跳过（计 skipped_duplicate）；
         新增：auth_status=authenticated, bind_status=unbound, sync_source=tax_platform
         our_company 按 buyer_tax_no 匹配我方公司字典
      ⑦ SyncLog 置 success（fetched/inserted/skipped 计数）
  → 前端轮询 GET /sync/{task_id}，完成后刷新列表 + 展示结果摘要
```

失败路径：验证码超时（5 分钟）/ 登录失败 / 平台改版抓取失败 → SyncLog=failed + message；会话文件不落盘。

### 4.3 API

| Method | Path | 说明 |
|---|---|---|
| POST | `/api/finance/invoices/sync` | 发起同步 `{date_from, date_to}`，权限：财务/管理员 |
| GET | `/api/finance/invoices/sync/{id}` | 轮询状态（含 waiting_sms 提示） |
| POST | `/api/finance/invoices/sync/{id}/sms` | 提交验证码 `{code}` |
| POST | `/api/finance/invoices/bind` | 采购单绑定发票 `{purchase_order_id, invoice_ids[]}` |
| DELETE | `/api/finance/invoices/{id}/allocations/{aid}` | 解绑（回滚 bind_status 与进度重算） |

### 4.4 绑定与进度回写

- 绑定：写 `InvoiceAllocation(target_type='purchase_order', amount=发票 total_amount, tax_amount=…)`，`bind_status→bound`；**支持一票绑多单时金额分摊**（本版弹窗限制一票绑一单，分摊结构预留）；
- 收票进度：采购单 `invoiced_amount += Σ绑定发票.total_amount`（解绑/作废走既有红冲重算逻辑，与 V2.5 同构）。

## 7. 验收场景（AC，实现后写入 39 号验收文档）

- AC-01 发起同步（无有效会话）→ 自动登录 → 弹验证码输入 → 输入后完成同步，发票入库且 `auth_status=authenticated`、`bind_status=unbound`、同步时间记录；
- AC-02 1 小时内二次同步 → 免登录直接拉取；
- AC-03 同一发票号重复同步 → 跳过不重复入库（幂等）；
- AC-04 发票列表：默认按开票日期倒序，可切换；列含税率（换算值）、税额在金额前、签约公司/开票单位/收票单位正确；
- AC-05 采购单弹窗：默认只列未确认发票，多选 2 张绑定 → 状态变已确认，收票进度 = Σ价税合计/采购单金额；
- AC-06 解绑 → 状态回未确认，收票进度重算；
- AC-07 验证码超时/密码错误 → SyncLog=failed，前端展示原因，无脏数据；
- AC-08 权限：仅财务/管理员可同步与绑定；采购员可发起绑定（自己数据范围）；viewer 只读。

## 8. 风险与边界

| 风险 | 应对 |
|---|---|
| 平台改版/反爬 | 抓取逻辑集中在单一 service 模块 + 失败落 sync_log.message；预留退化到 Excel 导入（browser-sessions 方式）的入口 |
| 验证码依赖人工 | 明确产品口径：同步必须有人在场输验证码；1 小时保活内多次同步免打扰 |
| 凭据安全 | 配置文件 + base64 混淆；不进日志不回传前端；内网部署风险可控 |
| 平台合规 | 只读查询自家账号的发票数据（与人工在页面查询导出等价），不做批量爬取他人数据 |
