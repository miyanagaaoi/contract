## 1. 项目背景与目标

公司合同分散在 Excel/纸质与个人电脑中，采购、财务、项目管理三方对合同的
**标的物、金额、付款、到货、质保**等关键信息缺乏统一台账，进度靠人传话，
框架合同与子合同关系、质保到期时间容易遗漏。

本系统目标是建立一个**内网部署、3~4 人使用**的合同台账与履约跟踪工具：

1. 统一登记与管理合同关键信息（标的物、金额、已付、付款比例、合同编号等）；
2. 支持合同标签化管理与多条件检索；
3. 支持框架合同与子合同的一对多绑定；
4. 跟踪合同进度状态并留存变更历史；
5. 跟踪质保生效/到期时间并做站内到期提醒；
6. 支持按筛选结果导出 Excel 台账；
7. 全员免登录直接使用（纯内网，不设账号与角色）。

## 2. 用户与分工（无账号体系说明）

| 用户 | 现实分工 | 主要使用内容 |
|---|---|---|
| 采购 | 经办合同、维护到货 | 录入合同、标签、到货情况 |
| 财务 | 付款信息维护 | 金额、累计已付、付款比例核对、导出台账 |
| 项目管理 | 履约与质保跟踪 | 进度状态更新、质保到期查看与处理 |

**决策：不做登录功能、不区分角色（纯内网信任模型）。**

- 内网任意电脑打开系统地址即可使用，无账号/密码/角色差异；
- 已知取舍与对策：
  1. 任何修改无法按"操作人"追溯 → 每个合同维护 **经办人** 字段（谁在跟进）；
  2. 变更历史记录 **时间、字段、前后值**（不记录操作人），保证"改了什么、何时改"可查；
  3. 日常全量备份兜底（见 `02-system-design.md` 第 10 节）；
- 若未来要求"谁改了什么"可审计，需重新引入账号体系（见 `04-tech-route.md` 演进路线，改造成本小）。

## 4. 业务规则（BR，规格核心）

### BR1 合同编号
- 合同编号**必填且全库唯一**。
- 编号格式建议统一为 `类型码-年份-流水`（如 `CG-2025-001`、`XS-2025-001`），提供编号重复校验提示。

### BR2 合同基本字段与口径
- 必填：合同编号、合同名称、合同类型（采购/销售/其他）、甲方名称、乙方名称、签订日期、标的物、合同金额。
- 金额默认人民币（元），保留两位小数；预留"币种"下拉（人民币/美元/欧元…），暂不影响计算。
- 甲方乙方：MVP 为自由文本（Q6：常用单位字典延后到 M1）。
- 经办人：自由文本 + 常用值联想（Q8）。
- 可选：内部备注、所属框架合同、质保信息、附件。

### BR3 付款与比例口径（已确认，Q1/Q3）
- 系统记录两个字段：`合同金额`、`累计已付金额`（手工维护单一字段，不做逐笔付款）。
- 口径确定：**付款比例 = 累计已付 ÷ 合同金额 × 100%**，由系统自动计算并显示；质保金不从此口径扣除。
- 若合同约定了质保金（`质保金金额 > 0`，默认从尾款扣留），系统同时显示提示行：
  `应付中仍含未付质保金 ¥X（占合同金额 Y%），如按约定到期后支付，请注意与已付口径区分。`
- 校验：累计已付 ≤ 合同金额时正常录入；超出时给出**警告但允许保存**（防止"质保金另计、总额超出"等特殊口径），并在变更历史中留痕。
- 到货情况（Q3）：`到货状态`（未到货/部分到货/已到货）+ `预计到货日期` + 备注；到货与状态机"发货→到货"相互独立但可对应。

### BR4 状态机（进度管理）
- 预置状态集合（顺序仅为默认流转参考，**不强制必须按序**）：
  `内部审批中 → 集团审批中 → 已签订 → 付款中 → 发货 → 到货（完成）`
- 另含（Q4）：`已终止/作废`（标记时必填终止原因）；状态字典可增删自定义状态。
- **任何状态下经办人都可手动将状态改为其他状态**（存在退回、跳步、回退的实际场景），每次变更必须记录：
  时间、原状态 → 新状态、备注（可选）。
- 已到货不等于合同结束：质保期仍在跟踪，合同可标记 `质保已释放` 后视为全部闭环。

### BR5 质保金跟踪（已确认，Q2）
- 质保金金额（元）或比例（%）二选一录入，系统换算另一值（比例 = 质保金 ÷ 合同金额）。
- 字段：质保生效日期、质保期限（月）；**质保到期日算法（Q2）：生效日按"加期限月、取到期当月最后一天"**（例：2025-06-01 + 12 个月 = 2026-05-31）。
- 质保处理标记：`未处理 / 已释放`（记录释放日期与备注）；已释放后不再进入提醒。
- 预警规则：质保到期日在未来 30 天内且未释放 → "即将到期"；已过到期日未释放 → "已到期"。均进入首页看板提醒。

### BR6 框架合同与子合同（一对多）
- 合同标记 `是否框架合同`；框架合同下可添加若干**子/执行合同**（每个子合同记录父框架合同 ID）。
- 一个子合同只能归属一个框架合同；子合同可为普通采购/销售合同。
- 解绑/改绑操作需在变更历史留痕。
- 框架合同详情页展示：子合同列表、子合同数量、子合同金额合计、各子合同当前状态分布。
- 框架合同本身也可有金额（预估总额），与子合同合计分开显示，不强制相等。

### BR7 标签管理（已确认，Q5）
- 标签为自由文本，全局去重；同一合同可添加**任意多个**标签；同一标签可挂在多个合同上。
- 预置常用标签示例：`采购`、`销售`、以及常用项目名（Q5：项目先以标签表达，M1 评估是否加独立"项目"字段）。
- 录入时可从常用标签库快速选择，也可直接新建标签；标签支持改名与删除（删除仅从字典移除，历史展示按名称匹配）。

### BR8 搜索与筛选
- 支持组合条件（AND 关系）：
  - 关键词：合同名称 / 合同编号 / 甲方 / 乙方（模糊匹配，可勾选"全文含标签"）；
  - 标签：多选，**默认"包含所选全部标签（交集）"**；
  - 签订日期区间、合同类型、当前状态、是否框架合同、是否含质保金；
  - 经办人筛选；快速筛：即将质保到期、质保已到期。
- 结果支持排序（签订日期、金额、最近更新）与**导出当前筛选结果**为 Excel。

### BR9 操作与责任（无登录环境）
- 系统无账号与角色：内网用户均可查看、新增、编辑、删除（软删除）、维护标签字典。
- 责任机制替代角色权限：每个合同维护 **经办人**（谁跟进）；变更历史记录**时间与前后值**，不记录操作人；
  涉及删除/停用必须填写原因（写入历史）。
- 由于无法识别"我"，不提供"我录入的合同"快捷筛，改为**按经办人姓名筛选**。

### BR10 删除与数据安全（已确认，Q7）
- 合同**不做物理删除**：提供"停用/删除（软删除 + 留痕）"，操作时必须填原因；
- **可恢复**：被停用/删除的数据保留 30 天，期间可恢复；超过 30 天由管理员/维护人确认后清理；
- 附件删除留痕；导出行为记录于系统日志（时间与动作，无操作人标识）。

### BR11 附件（初版范围）
- 支持上传 PDF / Word / Excel / 图片（每文件 ≤ 20MB，类型白名单）；
- 合同详情页内上传、下载、预览（PDF/图片可直接预览，其他类型提供下载）；
- 附件与合同绑定，删除留痕；
- 不做 OCR、不做附件正文全文检索（后期另行规划，见 `04-tech-route.md` 演进路线）。

### BR12 变更历史
- 关键字段变更（金额、已付、状态、质保日期、绑定关系、停用等）自动写入变更历史：
  字段、旧值、新值、变更时间、备注（可选）；因无登录，**不记录操作人**。
- 列表与详情页均可查看历史时间线；标签字典等维护类操作另记系统日志。

### BR13 环境与容量
- 纯内网部署，不依赖外网（无邮件/短信/IM 推送）；
- 并发 3~4 人，合同总量预期数百~千级，响应要求内网 < 1s；
- 浏览器：内网统一使用现代 Chrome / Edge；
- 系统支持 UTF-8 中文全流程。

## 5. 非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 易用性 | 3 类用户无培训成本：录入 < 3 分钟/单，搜索两步内完成 |
| 可靠性 | 业务数据每日自动备份；提供备份/恢复手册并定期演练 |
| 安全 | 依赖内网访问边界；上传白名单与随机文件名（防路径穿越）；参数校验 + ORM 防注入；**无登录/角色**（见 §2 取舍） |
| 可维护性 | 单体架构、结构化代码、数据模型迁移脚本（版本化）；文档随代码更新 |
| 可扩展性 | 付款可升级为逐笔记录、可重新引入账号与审计、附件可升级 OCR——均不需重写（见演进路线） |

## 6. 范围外（MVP 明确不做）

- 不做登录、账号、角色与任何权限控制（含字段级与数据隔离）；
- 不做审批工作流/电子签章/对接 OA；
- 不做邮件、短信、企业微信推送；
- 不做 OCR 与附件正文检索；
- 不做移动端 App（页面自适应即可）；
- 不做历史数据批量迁移（从零录入）。

## 7. 验收场景清单（AC，Given-When-Then）

> 用法见 `00-sdd-process.md`。标注 P0 = 原型验证必做，P1 = 正式版首期，P2 = 后续迭代。
> 每完成一个功能的全部场景，即保存一次 Git 版本（见 `03-development-plan.md` §3.1）。

### AC-01 新增合同（P0）
- Given 我打开系统（无需登录）
- When 我填写合同编号、名称、甲乙双方、签订日期、标的物、金额并保存
- Then 列表出现该合同，付款比例 = 0%，状态默认"内部审批中"，详情可打开

### AC-02 合同编号重复校验（P0）
- Given 已存在合同编号 CG-2025-001
- When 我再保存一个相同编号的合同
- Then 系统拒绝并提示"合同编号已存在"

### AC-03 已付与付款比例联动（P0）
- Given 合同金额 100,000，累计已付 0
- When 我把累计已付改为 50,000
- Then 列表与详情显示付款比例 50%；变更历史记录"累计已付 0 → 50000"及时间

### AC-04 状态流转与历史（P0）
- Given 合同状态为"内部审批中"
- When 我将其改为"集团审批中"并填写备注
- Then 状态更新；变更历史显示 时间/原状态→新状态/备注

### AC-05 多标签挂载（P0）
- Given 我在标签库中已有"采购"
- When 我为合同 A 添加"采购""项目B"两个标签，合同 B 只添加"采购"
- Then 两个合同都能被"采购"标签筛出；合同 A 还能被"项目B"筛出

### AC-06 组合搜索（P0）
- Given 系统内有若干合同
- When 我按"甲方包含 X + 签订日期 2025 年 + 标签含采购"查询
- Then 返回同时满足全部条件的合同；空条件返回全部
- And 导出按钮导出的 Excel 与当前筛选结果一致

### AC-07 框架合同绑定（P0）
- Given 存在框架合同 F-001
- When 我把子合同 C-1、C-2 绑定到 F-001
- Then F-001 详情显示子合同 2 份、金额合计正确；C-1/C-2 详情显示所属框架为 F-001

### AC-08 质保到期提醒（P0）
- Given 合同含质保金，质保生效日 2025-06-01、期限 12 个月（到期日按规则 = 2026-05-31），尚未释放
- When 系统当前日期为 2026-05-15
- Then 首页看板"即将到期"区出现该合同；当日期超过 2026-05-31 且未释放则进入"已到期"区
- And 我将其标记"已释放"并填释放日期后，该合同从提醒区消失

### AC-09 附件上传下载（P0）
- Given 一份待上传的 PDF（≤20MB）
- When 我在合同详情上传
- Then 附件列表出现该文件，可下载/预览；删除需填原因并留痕

### AC-10 免登录直开与变更留痕（P0）
- Given 内网任意一台电脑的浏览器
- When 直接打开系统地址并新增、修改、停用（删除）合同
- Then 无需登录即可完成全部操作（不区分角色）；每个动作在合同"变更历史"中留下时间与前后值；停用/删除需填原因

### AC-11 导出 Excel（P0）
- Given 列表筛选后共 N 条结果
- When 点击"导出 Excel"
- Then 得到 .xlsx，包含核心列（编号/名称/甲乙双方/类型/金额/已付/比例/状态/签订日期/经办人/质保到期/标签列），行数与筛选结果一致

### AC-12 变更历史时间线（P1）
- Given 合同被修改过金额、状态、绑定
- When 打开"变更历史"
- Then 按时间倒序列出每次变更的时间、字段、旧值、新值

### AC-13 标签字典维护（P1）
- Given 任意用户在标签管理页
- When 重命名标签"项目B"为"项目B-二期"
- Then 所有挂该标签的合同显示新名称；删除标签后从常用库消失

### AC-14 质保金比例换算（P1）
- Given 合同金额 200,000
- When 我录入质保金比例 5%
- Then 系统自动显示质保金金额 10,000，并给出"含未付质保金"提示

### AC-15 停用与恢复（P1，对应 Q7）
- Given 某合同被停用（软删除，已填原因）
- When 30 天内我在"已停用"列表执行恢复
- Then 合同回到正常列表，恢复动作写入变更历史；停用数据超过 30 天后不再显示可恢复入口

## 8. 原型验证目标（Mode 决策）

原型（MVP = 全部 P0 场景，见 `03-development-plan.md`）用于验证：

1. 台账字段与搜索能否覆盖日常管理（请采购、财务、项目管理各用 1~2 个真实合同试录）；
2. 框架绑定与质保提醒是否符合使用习惯；
3. 界面是否"录得快、找得到、导得出"。

通过标准（Go 信号）：三类用户演示中 ≥ 80% 场景无异议。
