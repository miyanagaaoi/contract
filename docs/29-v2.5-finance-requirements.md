# 29. V2.5 需求规格（PRD）：财务模块（付款单 / 收款单 / 发票管理 + 六条进度列）

> 上游：`docs/28-v2.5-finance-module-plan.md`（讨论稿，§10 口径冻结结论）
> 需求来源：`docs/2.4prompt .txt`
> 门禁：本文件是 **G2 规格评审**的唯一评审对象（`docs/00-sdd-process.md` §4.1）——
> 涉及金额、付款比例与权限边界，必须业务方确认 §8 后进入实现。
> 版本定位：**V2.5**（飞书接入 = V2.4）。

## 1. 版本目标与范围

### 1.1 目标

把"钱"的业务台账纳入系统，并让**采购单 / 销售订单列表直接看到履约与资金进度**：

1. 新增财务管理模块：付款单、收款单、发票管理（进项/销项）；
2. 付款/收款与采购单/销售订单**核销**，发票与单据核销；
3. 采购单列表新增 **收货进度 / 付款进度 / 收票进度**，销售订单列表新增 **发货进度 / 收款进度 / 开票进度**，均按百分比显示；
4. 两个列表的「更多」下拉新增**快速发起**入口，跳转对应表单并预填来源单据。

### 1.2 范围（6 项需求 → 20 条 AC）

| N | 需求 | 对应 AC |
|---|---|---|
| N1 | 付款单（新建/编辑/提交/财务审核/作废/反审核/打印） | AC-V2.5-01~07、19 |
| N2 | 付款单核销到采购单（M1 界面一对一，数据结构支持多单） | AC-V2.5-04、05 |
| N3 | 付款单权限（业务员发起、财务审核） | AC-V2.5-18 |

| N5 | 收款单（与付款单镜像，核销销售订单，回写 `received_amount`） | AC-V2.5-08、13 |
| N6 | 进项发票登记（票面信息 + 认证状态 + 关联采购单 + 附件） | AC-V2.5-09、11 |
| N7 | 销项发票登记（关联销售订单，回写 `invoiced_amount`） | AC-V2.5-10、11 |

### 1.3 范围外（本版明确不做）

会计凭证 / 总账 / 科目体系 / 试算平衡；税务申报与发票验真接口（百望、航信）；银行流水导入与自动对账；
多币种汇率换算（既有单据也是"只记录不换算"，`docs/11` O9）；应收应付账龄分析（→ M3）。

### 1.4 对既有规格的修订（⚠️ 口径级）

`docs/11-erp-requirements.md` §14.5（第 825 行）把"财务模块：应收应付、收付款单、开票、核销、财务凭证"
列为 V2.0 **明确不做**。本版**部分解禁**：

- ✅ 纳入：收付款单、开票（发票登记）、核销、按单据的应收应付进度；
- ❌ 仍不做：财务凭证与总账（第 1 项的末半段保持不变）。

同时修订 `docs/11` D7（原"MVP 不含财务"）与合同"累计已付"手工维护的约定（见 §3 BR-V2.5-12，M2 执行）。

## 3. 业务规则（BR-V2.5）

| 编号 | 规则 |
|---|---|
| BR-V2.5-01 | **审核即记账**：付款单/收款单 `approved` 时把核销金额计入目标单据；草稿/已提交/已驳回**不计入**进度。发票以"确认"（`confirmed`）为记账点，认证状态不影响进度。 |
| BR-V2.5-02 | **红冲可逆**：已审核单据的**反审核**必须**精确回退**已计入的金额（同一事务内，幂等）。**作废只对草稿/已提交生效**（`doc_service._ensure_status` 既有约束），此时从未记账，无需红冲。 |
| BR-V2.5-03 | **超额允许但标红**：核销金额可超过目标单据金额（先付后补单是真实业务），进度可 >100%，列表标红并可按"超额"筛选；不硬拦截。 |
| BR-V2.5-04 | **下游保护**：目标单据（采购单/销售订单）存在未作废的付款单/收款单/发票核销时，**禁止反审核或作废目标单据**，提示先处理下游（与 AC-V2-24 同款口径）。 |
| BR-V2.5-05 | **进度口径**：金额类进度的分子分母均为**含税（价税合计）**；收货/发货进度为**数量**口径（Σ`received_qty`/Σ`qty`、Σ`shipped_qty`/Σ`qty`）。 |
| BR-V2.5-06 | **展示口径**：`0%` 灰、`0<p<100` 蓝、`p=100` 绿、`p>100` 红（显示真实值）；分母为 0 显示 `—`；保留 1 位小数。 |
| BR-V2.5-07 | **发票**：`(direction, invoice_no)` 唯一，重复登记提示已存在；认证状态 `pending → verified` 由财务手工流转；发票"确认"后才计入收票/开票进度。 |
| BR-V2.5-08 | **权限最小化**：财务动作独立权限点；业务员仅有"发起"权限（`create`），无 `approve`；后端强制校验（AC-V2-41 不变）。 |
| BR-V2.5-09 | **数据范围一致**：财务列表与导出、进度列都走各单据既有数据范围；导出条数与筛选一致（AC-V2-40）。 |
| BR-V2.5-10 | **幂等**：同一单据重复调用审核/反审核不产生重复记账（以 `posted` 标记与状态机双重保证）。 |
| BR-V2.5-11 | **编号**：`PAY` / `RCP` / `INV` 前缀，按月重置 + 6 位序号，可在「系统管理 → 编号规则」调整前缀与位数。 |
| BR-V2.5-12 | **合同联动**（已落地）：付款单审核后按**增量**把付款单总额累加到合同「累计已付」，反审核精确回退；**不重算、不覆盖**人工补录的历史付款；未关联合同的付款单不影响任何合同；收款单不回写（合同只有"累计已付"字段，销售侧"累计已收"本版不做）。 |

## 4. 详细需求

### 4.1 付款单（N1~N4）

| 项 | 口径 |
|---|---|
| 表头字段 | 单号(PAY)、单据日期、**签约公司/付款主体**（`subject_code`，必填，沿用 V2.3 口径）、供应商（必填）、结算方式（银行转账/现金/承兑/其他）、付款账户（自由文本）、币种（默认 CNY）、付款金额（含税）、经办人（默认当前账号）、关联合同（选填）、来源单据（快照）、备注、附件 |
| 核销明细 | 至少一行：`目标类型`（采购单 / 入库单）+ 目标单号 + 核销金额；M1 界面只允许选**一张**单据（多单放开在 M3），数据结构支持多行 |
| 状态机 | 草稿 → 已提交 → 已审核（记账）→ 反审核 / 作废（红冲）；驳回回草稿 |
| 编辑限制 | 仅草稿可编辑（沿用 `EDITABLE_STATUSES`）；已审核须先反审核 |
| 打印 | 付款凭单版式（打印模板可配置表头/字段） |

### 4.2 收款单（N5）

与付款单镜像：客户（必填）、收款账户、核销目标为**销售订单 / 出库单**、回写 `sales_orders.received_amount`。

### 4.3 发票管理（N6~N7）

| 项 | 口径 |
|---|---|
| 方向 | `in` 进项（供应商开具）/ `out` 销项（我方开具），同一张表区分，列表默认按方向分页签（库列名 `invoice_direction`，命名避让 `docs/30` §2.1） |
| 票面字段 | 发票代码、发票号码、开票日期、票种（增值税专用/普通/电子）、税率、金额（不含税）、税额、**价税合计** |
| 关联 | 进项 → 采购单；销项 → 销售订单；可多张单据分摊核销（M1 界面一对一，结构支持多行） |
| 状态 | `draft` 草稿 → `confirmed` 已确认（计入进度）→ `voided` 作废（红冲）；`auth_status`：`pending` 待认证 / `verified` 已认证（手工流转，不影响进度） |
| 附件 | 票据影像（复用附件模块） |
| 重复校验 | `(direction, invoice_no)` 唯一，重复报 422「该发票号已登记」 |

### 4.4 六条进度列（N8）

| 列表 | 列 | 分子 / 分母 |
|---|---|---|
| 采购单 | 收货进度 | Σ`received_qty` / Σ`qty` |
| 采购单 | 付款进度 | `paid_amount` / `total_amount` |
| 采购单 | 收票进度 | `invoiced_amount` / `total_amount` |
| 销售订单 | 发货进度 | Σ`shipped_qty` / Σ`qty` |
| 销售订单 | 收款进度 | `received_amount` / `total_amount` |
| 销售订单 | 开票进度 | `invoiced_amount` / `total_amount` |

- 列位置：紧跟「金额」列之后、状态列之前；
- 悬浮提示写明分子分母（BR-V2.5-05/06）；
- 列头可点排序（M2 可选）；支持"未完成 / 已完成 / 超额"筛选（M2）；
- **导出同步**：Excel 增加对应三列（百分比文本 + 分子分母原始数值）。

### 4.5 「更多」快速发起（N9）

| 列表 | 「更多」新增 | 跳转 | 预填 |
|---|---|---|---|
| 采购单 | 发起付款单 | `/finance/payments/new?source_type=purchase_order&source_id=<id>` | 供应商、签约公司、来源单号、金额 = 未付金额、合同 |
| 采购单 | 登记进项发票 | `/finance/invoices/new?direction=in&source_type=purchase_order&source_id=<id>` | 供应商、方向=进项、来源单号、价税合计 = 未收票金额 |
| 销售订单 | 发起收款单 / 登记销项发票 | 同上（方向=out） | 客户 + 对应金额 |

- 仅对 `approved` / `completed` 且未作废的单据显示；无 `finance.*.create` 权限**不渲染**；
- 预填只是默认值，可改（支持部分付款 / 部分开票）；来源单号在单据上留快照。

## 5. 验收场景（AC-V2.5-01 ~ 20）

> 格式：Given / When / Then（可直接转 pytest 或人工冒烟）。

**AC-V2.5-01 付款单新建与必填校验**
Given 采购单 PO-1（已审核，金额 10000，未付款）／When 采购员填付款单（供应商+金额+签约公司）并保存／Then 编号为 `PAY` 前缀、状态草稿、来源单号为 PO-1；缺供应商或签约公司时 422。

**AC-V2.5-02 审核记账与进度变化**
Given 付款单 10000（草稿）／When 财务审核／Then 采购单 `paid_amount=10000`、付款进度 `100%` 绿色、付款单状态已审核、写变更历史与操作日志。

**AC-V2.5-03 部分付款**
Given 采购单 10000／When 付款 3000 并审核／Then 付款进度 `30%`；详情抽屉能看未付金额 7000。

**AC-V2.5-04 核销明细落库**
Given 付款单核销到 PO-1 3000／When 查看付款单详情与目标单据详情／Then 双方都能看到核销明细（单号、金额、时间、操作人）。

**AC-V2.5-05 反审核红冲（作废只作用于未审核单据）**
Given 付款单已审核（进度 30%）／When 反审核并填原因／Then 进度回到 `0%`、`paid_amount=0`、状态回到"已提交"；再次反审核被拒（状态不允许），不出现负数。
Given 草稿付款单／When 作废（填原因）／Then 状态作废且**不影响**任何进度（从未记账）；已审核单据不允许直接作废，提示先反审核。

**AC-V2.5-06 超额付款**
Given 采购单 10000 已付 10000／When 再付 2000 并审核／Then 允许保存，付款进度显示 `120%` 且标红，列表可按"超额"筛出。

**AC-V2.5-07 下游保护**
Given 采购单 PO-1 有未作废付款单／When 反审核或作废 PO-1／Then 422「已存在付款单，请先处理下游单据」。

**AC-V2.5-08 收款单与收款进度**
Given 销售订单 SO-1（金额 8000）／When 收客户款 8000 并审核／Then `received_amount=8000`、收款进度 100%、SO-1 状态不受影响。

**AC-V2.5-09 进项发票登记与认证**
Given 发票号已存在／When 重复登记进项发票／Then 422「该发票号已登记」；`auth_status` 可由财务在 `pending ↔ verified` 间手工流转，流转不改变收票进度。

**AC-V2.5-10 销项发票与开票进度**
Given 销售订单 8000／When 登记销项发票 8000（价税合计）并确认／Then 开票进度 100%。

**AC-V2.5-11 收票进度口径**
Given 采购单 10000（含税）／When 登记进项发票价税合计 5000 并确认／Then 收票进度 `50%`（口径为含税，AC-V2.5-11 的断言含"用不含税金额 4424.78 不得显示为 50%"）。

**AC-V2.5-12 采购列表三列**
Given 采购单分别处于 0% / 部分 / 完成 / 超额四种状态／When 打开采购单列表／Then 三列百分比与颜色符合 BR-V2.5-06，分母为 0 的单据显示 `—`。

**AC-V2.5-13 销售订单三列**
同 AC-V2.5-12，作用于 发货 / 收款 / 开票 三列。

**AC-V2.5-14 「更多」快速发起付款单**
Given 采购单 PO-1（已审核、未付款 10000）／When 点「更多 → 发起付款单」／Then 跳转新建页并预填供应商/签约公司/10000/来源 PO-1；保存后 PO-1 详情显示"已生成付款单 PAY-xxx"。

**AC-V2.5-15 「更多」快速发起收款单 / 发票**
同 AC-V2.5-14，作用于销售订单（收款单、销项发票）与采购单（进项发票，方向预置 `in`）。

**AC-V2.5-16 导出与列表一致**
Given 列表筛选出 N 条（含超额）／When 导出 Excel／Then 条数一致、进度三列与页面显示一致、数据范围一致（越权不可导出）。

**AC-V2.5-17 进度重算**
Given 手工改动核销明细造成回写与明细不一致（模拟）／When 调用重算接口／Then 回写值被校正为明细合计，接口返回修正条数；无权限账号 403。

**AC-V2.5-18 权限与数据范围**
Given 采购员账号（无 `finance.payment.approve`）／When 直接调审核接口／Then 403；「更多」里不显示"发起付款单"以外的财务按钮；业务员只能对自己数据范围内的单据发起（跨范围 403/不可见）。

**AC-V2.5-19 合同累计已付（M2，待 §8 确认）**
Given 合同 HT-1 累计已付 0／When 付款单审核（关联 HT-1）／Then 合同累计已付 +10000；反审核后回退。

**AC-V2.5-20 幂等与并发**
Given 同一付款单被两次提交审核请求／When 并发到达／Then 只记账一次（`paid_amount` 不翻倍），第二次返回"状态不允许"或幂等成功。

## 6. 与既有规格的兼容性

1. **既有单据零影响**：三类新单据走新的 `/api/finance/*` 前缀与独立权限点；`DocMixin` 只增不改。
2. **列表契约扩展**：采购单/销售订单列表与导出**新增** `progress` 字段与三列，既有字段与字段顺序不变（前端未升级时忽略新字段）。
3. **既有下推链不变**：财务核销不参与 `push_service` 的下推数量校验，只在作废/反审核时做下游保护。
4. **看板与飞书**：M2 只做"付款/收款/发票审核结果"通知（可选）；看板资金卡片放 M3。
5. **存量数据**：`paid_amount`/`received_amount`/`invoiced_amount` 初始为 0，与"历史付款未在系统中登记"一致；上线时若有历史付款，需一次性初始化（见 30 号文档 §2.4 与 31 号文档的运维项）。

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 事务 | 核销明细、回写、状态变更、审计日志**同一事务**；失败整体回滚（沿用 `_guard` 的 422 + rollback） |
| 精度 | 金额 `Numeric(16,2)`（分）；核销行金额合计与表头金额允许差额（部分核销/未核销预付款），差额在单据上显示为"未核销" |
| 性能 | 列表进度由**回写字段**直接读出（零 join、零聚合）；不引入 N+1 |
| 审计 | 审核/反审核/作废/确认/认证状态变更均写操作日志 + 变更历史 |
