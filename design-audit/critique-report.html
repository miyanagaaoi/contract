五维详评

1 · 哲学一致性

5/10
Functional · 方向有一半，另半页漂移

业务页的视觉语言是统一且被认真执行的：el-card shadow="never" + size="small" 表格 + 权限驱动按钮 + 统一状态标签。但同一个产品里并存三套语域——深色工具壳（AppLayout.vue:24-25）、营销式登录卡（LoginView.vue:79-86 渐变叠 0 18px 40px rgba(0,0,0,.25)）、裸 Element Plus 字典页（SettingsView.vue:105,107 用 <b> 当标题）。同一业务概念也有两种范式：合同里往来单位是「档案下拉 + 快照」，采购单里币种/结算方式却可自由输入。

Keep权限驱动按钮 + 后端硬校验的双层放行（DocListPage.vue:133-139,334-342）——体验层可退化、边界在后端。
Fix把三套语域收敛为一套工具型语言：登录/改密/403 三页统一走 --ctms-* 令牌，去掉营销量级投影与 64px 巨型字。
Quick win删掉 LoginView.vue:86 的 0 18px 40px rgba(0,0,0,.25)，换成与卡片语言一致的细边框 + 轻投影。

2 · 视觉层级

5/10
Functional · 页内一致，外壳无标题语义

标题(15px/600) + 副标题(12.5px/#909399) 在 12 个页面逐字一致，这是真实的一致性资产。但外壳没有层级：AppLayout.vue:22 用 div 承载应用名，实测全站 h1/h2 计数为 0，每页自造标题（<b> / 64px div / 18px h1 三套写法）。顶栏三件 13px 级灰字（组织名 + tag + 用户名，TopBar.vue:35,36,72）并列无主次。数据页也更平：合同台账把金额与付款比例压成同级小字（ContractsView.vue:808-819），而首页同类数字却放大到 28px。

Keep「一主色 + 灰阶辅助」的克制用色，以及各页统一的标题/副标题结构。
Fix每页补语义标题（h1 给页面名、h2 给卡片区块），并把金额列提升为行内第一视觉层（加深 + 右对齐 + 等宽数字）。
Quick win顶栏只保留一层信息：组织名降为 12px 次要色，用户名升为唯一 13px 主文字，角色标签收纳为 +N。

3 · 细节执行

4/10
Broken · 可见的胶带与绳子

21 个裸色值、12 种字号、0 个设计令牌；#909399 出现 24 次、12.5px 24 次，还夹带 11.5/13.5px 亚像素档；.mb{margin-bottom:12px} 被复制 8 份。全站数值列无一处 tabular-nums，金额无法纵向比对。格式化函数 7 份副本两种口径（空金额在 DocItemsTable.vue:86 渲染 0.00、在 RelatedDocs.vue:22 渲染 —），日期 3 种截断长度。8 个功能色作为文字全部低于 4.5:1（#e6a23c 仅 2.19:1）。

Keep数量精度跟随物料单位小数位（DocItemsTable.vue:58-65,172-182）——录入端与校验端同源，杜绝脏数据。
Fix落地 :root 令牌集（文字/功能色/6 档字号/4 倍间距）并覆盖 --el-*；utils/format.ts 收敛 7 份格式化函数；全局数值列 tabular-nums。
Quick win文字级功能色成组加深：#909399→#7a7f87、#f56c6c→#c45656、#e6a23c→#b88230、#67c23a→#4e9a51，一次拿到 AA。

4 · 功能性

5/10
Functional · 能干活的路径都在，护栏不在

为高频录入做的设计是真的：查询支持 Enter、下拉统一 filterable、行项校验精确到「第 N 行：请选择物料档案」、物料/单位支持「现场快建不跳转」、库存侧重算校验 + 按流水修复。但护栏缺失：全项目 beforeunload/onBeforeRouteLeave 命中为 0（录 20 行后误点返回即静默丢失）；router/index.ts:311-316 瞬时断网即清 token 踢回登录；12 个列表页 0 处批量操作，行内 9 个链接按钮挤在 320px 操作列（DocListPage.vue:472）；0 个页面把筛选写进 URL，浏览器回退直接离开页面；详情页侧栏高亮全丢（AppLayout.vue:16）。

Keep精确到行的中文校验提示与「现场快建」不跳转设计——直接告诉用户改哪一行。
FixP0未保存离开保护 + 401/网络错误分流 + UTC 日期修正 + 批量操作（改 DocListPage 一个壳覆盖 8 页）。
Quick win筛选与分页 router.replace({ query }) 双向同步 + AppLayout.vue:16 改最长前缀匹配，同时拿回深链与导航定位感。

5 · 创新性

5/10
Competent and unmemorable · 保守合理，但没有「赚到」的动作

整体是成熟的中后台范式，保守本身正确、不额外扣分；但也没有一个为「合同 + 进销存」这个业务定做的小动作：无命令面板、无键盘优先录入、无密度切换、无保存视图，连 220px 侧栏（AppLayout.vue:21）都不可折叠。真正有想法的是三处，且都能指向具体实现：合同框架树的展示层语义边界（ContractsView.vue:56-99,845 用 alert 显式声明不改变筛选/导出语义）、盘点单账面冻结 + 差异行高亮（TakeForm.vue:81-115,405-406）、库存重算校验 + 按流水修复（BalanceView.vue:191-214）。

Keep那三处「有设计想法」的实现——它们是这套 UI 唯一让人记住的地方，别在重构中抹平。
Fix把三处思路扩展成系统能力：框架树 → 全局主数据树浏览；盘点差异 → 通用「差异高亮 + 一键修正」模式。
Quick win给高频录单页加「最近使用」与键盘快捷键提示（如 Ctrl+Enter 保存并提交），成本极低但立刻有产品感。
