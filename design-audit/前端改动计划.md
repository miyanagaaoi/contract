## 0. 计划摘要

| 项 | 内容 |
|---|---|
| 目标 | 止血（丢/错数据）→ 立标尺（令牌+可读性）→ 提效率（批量+深链）→ 收敛一致性 |
| 批次 | 5 批（批次 0 安全网、1 数据正确性、2 效率、3 观感与可访问性、4 一致性与工程化） |
| 任务数 | 25 个（P0 级 7 个、P1 级 9 个、P2 级 9 个） |
| 总量估算 | 约 **11–14 人日**（1 名熟悉该代码库的前端；含 e2e 同步与回归） |
| 改动杠杆 | 12 个列表页 / 8 个表单页是**配置壳**，真实交互集中在 5 个组件里——一致性问题一律改壳，不逐页改 |
| 出口标准 | 每批次结束：`npm run test:e2e` 全绿 + `node design-audit/shoot.mjs` 指标对比不倒退 |

### 三条硬约束

1. **e2e 是当前唯一的质量安全网**：`web/` 无 ESLint、无 `vue-tsc`、无 `prettier`、仓库无 CI 配置；`tsconfig.json` 未被任何脚本调用。11 个 Playwright spec（`01-auth` … `11-master-product`）大量依赖**可见文本与像素断言**，是本计划最大的约束来源（见 §4 改动禁区与影响登记表）。
2. **不推翻 Element Plus**：审查结论是「把 EP 用对」（令牌层 + 状态层 + 可访问性层），不是替换组件库。
3. **不做无收益的美化**：如把「＋ 新增合同」的全角加号改成半角、改导出按钮文案 —— 收益为 0 但会直接打断 e2e。此类「字符级统一」本次**明确不做**。

## 3. 任务卡

### 批次 0 · 安全网与地基

#### T0-1 引入 `vue-tsc` 类型检查（建议先做）
- **落点**：`web/package.json`（新增 devDependency + script `"typecheck": "vue-tsc --noEmit"`）
- **理由**：本计划涉及组件 props、`Dict` 松散类型边界、`utils` 新导出与跨 20 个壳文件的重命名，没有类型检查只能靠 e2e 兜底。
- **风险**：新增依赖需负责人确认；首次运行可能暴露大量既有类型错误 → **先跑一次评估数量，若 >50 条则本任务降级为「仅对新增/改动文件开启」**（`tsconfig` 增量路径），不阻塞后续批次。
- **验收**：`npm run typecheck` 通过或错误数不高于基线。

#### T0-2 建立 `src/utils/format.ts`
- **落点**：新建 `web/src/utils/format.ts`
- **导出**：`fmtMoney(v)`（`null/undefined/''/NaN → '—'`）、`fmtQty(v, decimals)`、`fmtPrice(v)`、`fmtDate(v)`（`YYYY-MM-DD`）、`fmtDateTime(v)`、`todayLocal()`。
- **实现要点**：全部基于 `Intl.NumberFormat('zh-CN', { minimumFractionDigits: 2, maximumFractionDigits: 2 })` 与 `Intl.DateTimeFormat('zh-CN')`（同时消除「硬编码日期/数字格式」违规）；`todayLocal()` 用本地年月日拼接，**不得使用 `toISOString()`**。
- **注意**：本批次只**创建**，不替换调用点（替换在 T1-3）。
- **验收**：单元级自测（可在 Node 中直接调用打印 6 种边界：`null` / `undefined` / `''` / `NaN` / `0` / `1234567.891`）。

#### T0-3 定义设计令牌（只加不换）
- **落点**：`web/src/style.css`
- **改动**：加入 `:root { --ctms-text/-secondary/-muted/-placeholder; --ctms-primary/-danger-text/-warning-text/-success-text; --ctms-fs-xs…-xl; --ctms-gap-xs…-md; --ctms-radius; color-scheme: light; }`，并追加全局 `.el-table { font-variant-numeric: tabular-nums }`（具体值见主报告 P0-5 的代码块）。
- **约束**：本批次**不动任何现有样式**，仅新增变量与全局数值字体特性 → 视觉零变化、e2e 零影响。
- **验收**：`report.json` 中 `fontSizes` 分布与基线一致；抽查金额列渲染无变化。

#### T0-4 基线快照
见 §1。**产出**：`design-audit/e2e.baseline.json`、`design-audit/report.baseline.json`。

#### T0-5 token 单真源模块（消除双真源与循环依赖）
- **落点**：新建 `web/src/utils/token.ts`（`getToken()` / `setToken()` / `clearToken()` / `onTokenCleared(cb)`）；`web/src/api.ts:22-29,36-42` 与 `web/src/stores/auth.ts:41,56-60` 改为依赖它。
- **为什么必须新模块**：`stores/auth.ts` 已 `import { TOKEN_KEY, http } from '@/api'`，若 `api.ts` 反向 import store 会造成**循环依赖**；token 访问必须下沉到无依赖的模块。
- **验收**：登录/登出/401 三条路径下 `localStorage` 与 store `token` 始终一致（当前 `api.ts:38` 只清 localStorage 不回写 store，已确认会出现分裂态）。

### 批次 3 · 观感与可访问性

#### T3-1 令牌替换（**必须分三步走，每步独立提交 + 回归**）

#### T3-3 操作列收纳（**严格限定范围**）
- **做**：收纳**低频且未被 e2e 引用**的动作 —— 打印、反审核、作废、状态查看。

### 裁剪项（经实施期证据评估后不做，附理由）

1. **T4-4 图标按需引入（仅完成分包）**
   真正按需需要维护一份图标白名单，而 `MenuTree` 的图标名来自**后端返回的字符串**（`app/permissions.py`），漏一个就会让菜单图标静默空白，且 e2e 不覆盖图标。内网系统首屏体积不敏感 → 先做零风险的 `manualChunks` 分包，按需引入留待有明确体积诉求时再做。

2. **T4-5 栅格断点（仅完成弹窗宽度与看板统计卡）**
   15 个 dialog + 3 个 drawer 宽度已改为 `min(Npx, 92vw)`；看板 4 张统计卡已加 `:xs/:sm`。其余栅格的 `:span` 改动会触及 `02-dashboard.spec.ts:18` 的卡片数量断言，而内网以桌面为主，收益不抵风险。

3. **T4-9 跳转语义**
   `ForbiddenView` 的两个按钮 `<a>` 化会强制修改 `04-permission.spec.ts:70` 的既有断言；403 错误页的中键开新标签收益极低。`TopBar` 的「修改密码」位于 `el-dropdown-menu` 内（渲染为 `li`），技术上无法用 `<a>` 实现，属组件能力限制。

### 实施期对审查结论的两处修正

1. **计划外后端修复**：篡改 token 访问 `/api/auth/me` 返回 **500** 而非 401（`app/security.py` 的 `decode_token` 对畸形 base64 抛 `binascii.Error`，未归一到 `TokenError`）。原前端"任何错误都踢登录"掩盖了它；本次修复并重启后端，34 个后端认证测试全绿。
2. **审查结论纠错**：子代理判定 `permView` 死 prop 意味着「查看权限实际未生效」——经核实**不准确**：路由 `meta.perm` 已强制校验。正确处理是**删除**该冗余 prop（T4-3 已按此执行），而非按计划所写的"接线优先"。
