# CTMS 前端设计审查与优化建议

> 审查对象：`web/`（Vue 3.5 + Element Plus 2.9 + Vite 6 + Pinia，内网 ERP：合同管理 + 进销存）
> 审查方式：源码逐行审查（55 个源文件）+ 真实运行态取证（Playwright 登录 `http://127.0.0.1:5173`，19 张截图 + DOM 指标采集，视口 1440/1280/1024）
> 审查标尺：
> - **Vercel Web Interface Guidelines**（`web-design-guidelines` 技能钉版清单）
> - **critique 5 维专家评审框架**（哲学一致性 / 视觉层级 / 细节执行 / 功能性 / 创新性，各 0–10）
> - 领域校准：内网、数据密集、长时间高频录入的工具型系统 —— 不以营销页的表现力为标准，但一致性、层级、密度、可用性从严。
>
> 本次审查**未修改任何业务代码**，全部产物集中在 `design-audit/`。

---

## 一、总体结论

**一句话**：地基是对的（权限单源、配置驱动的 5 个页面壳、路由守卫、破坏性确认范式），但**没有设计决策层**——配色无令牌、排版无刻度、状态无反馈、焦点不可见；同时**三套语域拼在一个产品里**（深色工具壳 / 营销式登录卡 / 裸 Element Plus 表单页）。

### 5 维评分

| 维度 | 分数 | 判定带 | 一句话依据 |
|---|---|---|---|
| 哲学一致性 | **5** / 10 | Functional | 「`el-card shadow="never"` + `size="small"` + 权限驱动按钮」这套语言在业务页被认真执行；但同产品内并存三套语域：工具壳（`AppLayout.vue:24-25`）、营销式登录卡（`LoginView.vue:79-86` 渐变叠 `0 18px 40px rgba(0,0,0,.25)`）、裸 EP 字典页（`SettingsView.vue:105,107`）。 |
| 视觉层级 | **5** / 10 | Functional | `标题(15px/600) + 副标题(12.5px/#909399)` 在 12 个页面逐字一致；但**外壳无 `h1`**（`AppLayout.vue:22` 是 `div`），每页自造标题三套写法，顶栏三件 13px 级灰字并列（`TopBar.vue:35,36,72`），关键金额与付款比例被压成同级小字（`ContractsView.vue:808-819`）。 |
| 细节执行 | **4** / 10 | Broken | 12 种字号、21 个色值、0 个设计令牌；`#909399`+`12.5px` 这对组合被复制 24 次；全站数值列**无一处** `tabular-nums`；格式化函数 7 份副本两种口径；UTC 日期 bug 4 处；8 个功能色作为文字全部低于 4.5:1。 |
| 功能性 | **5** / 10 | Functional | 核心录单路径通、行项校验精确到行、数量精度跟随单位小数位（这些是真正为高频设计的）；但**12 个列表页 0 处批量操作**、**0 个页面筛选可深链**、未保存离开无保护（表单页 + 字典页）、瞬时断网即被踢回登录页、详情页侧栏高亮丢失。 |
| 创新性 | **5** / 10 | Competent and unmemorable | 成熟中后台范式，保守选择不加分；真正有想法的三处：合同框架树视图、盘点账面冻结+差异高亮、库存重算校验+按流水修复。 |
| **综合** | **4.8** / 10 | — | 可上线、可干活，但**每改一次视觉要动 15+ 个文件**，且缺少批量操作、深链、导航定位与状态反馈这四个高频杠杆。 |

> 评分纪律：不做通胀。5 分是「方向对但一直漂移」，4 分是「可见的胶带与绳子」。**全站无一项达 7 分（strong = 偶发漂移）**，这本身就是最重要的结论。三个模块独立评分分别为 4.6（框架层）/ 5.0（单据组件）/ 5.2（业务视图）——框架层最弱，因为它决定了全站的观感上限。

### 2.2 运行态 DOM 实测（1440×900）

| 页面 | 字号分布（DOM 节点数） | `h1/h2` | `aria-label` | <28px 点击目标 |
|---|---|---|---|---|
| 首页看板 | 16px×199、14px×42、12px×38、28px×10 | **0 / 0** | **0** | 1 |
| 合同台账 | 12px×**602**、14px×178、16px×69 | **0 / 0** | 31（EP 自带） | **19**（30×18px 链接按钮） |
| 账号管理 | 12px×**534**、14px×137、12.5px×29 | **0 / 0** | 2 | **42** |
| 系统管理 | 12px×**1544**、14px×293 | **0 / 0** | 48 | 0 |
| 入库单（新增） | 12px×371、14px×156 | **0 / 0** | 14 | 1 |

三个直接结论：

1. **页面没有标题语义**：所有「页面标题」都是 `div.title`（15px/600），整站 `h1`/`h2` 计数为 0（仅改密页有 1 个 `h1`）。屏幕阅读器无法建立文档大纲，也无法用快捷键跳转。
2. **字号主体是 Element Plus 默认值**（12px/14px 占绝对多数），项目自定的 12.5px/13px/15px 只是局部补丁 —— 视觉上的「碎」不是设计选择，而是缺少标尺的副作用。
3. **行内操作按钮 30×18px**，低于 32px 最小触控目标；账号管理一页出现 42 个。

| `#ffffff` / `#409eff` | **2.78:1** | 主按钮文字 | ✗ 不达标 |
| `#f56c6c` / `#ffffff` | **2.90:1** | 危险色文字 | ✗ 不达标 |

## 三、优化建议（按「每小时投入换来的收益」排序）

### P0 —— 会丢数据 / 产生错误数据 / 阻塞效率

**P0-1 补未保存离开保护（唯一会静默丢数据的路径）**

- 现状：`DocFormPage.vue:271`（返回列表）、`:374`（提交）无脏检查；全项目 `beforeunload` / `onBeforeRouteLeave` 命中数为 **0**。
- 后果：录了 20 行明细后误点「返回列表」，数据直接消失，无任何提示。
- 改法：在 `DocFormPage.vue` 记录 `dirty`（表头 `reactive` 任一字段变化或 `items.length` 变化即置位），加：
  - `onBeforeRouteLeave` → `ElMessageBox.confirm('有未保存的修改，确定离开？')`
  - `window.addEventListener('beforeunload', …)` 兜底刷新/关标签
  - 提交进行中给两个保存按钮加互锁（`saving` 期间禁用另一个），避免「保存草稿」与「保存并提交」并发

**P0-2 修 UTC 日期 bug（会开出错误日期的单据）**

- 位置：`DocFormPage.vue:108`、`PushDialog.vue:51`、`PushDialog.vue:106`、`DashboardView.vue:76`
- 现状：`new Date().toISOString().slice(0, 10)` 取的是 **UTC** 日期，东八区 00:00–08:00 期间默认日期会早一天。
- 改法：统一走 `src/utils/format.ts` 的 `todayLocal()`（用 `getFullYear/getMonth/getDate` 拼接，或 `Intl.DateTimeFormat('zh-CN').format(new Date())`）。

**P0-3 收敛 7 份格式化函数为 `src/utils/format.ts`**

- 现状：7 份 `fmtMoney` 两种口径（`toLocaleString` vs `toFixed(2)` 无千分位）、日期 3 种截断长度（`slice(0,10)` / `slice(0,19)` / `slice(11,19)` 拼接）、`UserView.vue:239`、`SystemView.vue:304,351` 完全不格式化直出原始串。
- 一致性缺陷：空金额在 `DocItemsTable.vue:86`、`ContractDetailDrawer.vue:20` 渲染 `0.00`，在 `RelatedDocs.vue:22`、`MasterTablePage.vue:227` 渲染 `—` → **空与零不可辨**；`RelatedDocs.vue:24` 的孪生实现漏了 `Number.isNaN` 分支，脏数据会显示字面量 `NaN`。
- 改法：新建 `web/src/utils/format.ts` 导出 `fmtMoney(v)`（空 → `—`）、`fmtQty`、`fmtDate`、`fmtDateTime`、`todayLocal`，全部基于 `Intl.NumberFormat('zh-CN')` / `Intl.DateTimeFormat('zh-CN')`（同时满足 Guideline 的「禁止硬编码日期/数字格式」）。顺带删除各 List 页里的本地 `fmtDate`（`InList.vue:7-9`、`OutList.vue:7-9`、`TransferList.vue:9-11`、两个 `RequestList.vue`）。

**P0-4 给数据密集列表加批量操作（最大效率缺口）**

- 现状：12 个列表页 **0 处** `type="selection"`；行内动作全挤在固定宽操作列（`DocListPage.vue:472` 宽 320px 内最多 9 个链接按钮：查看/编辑/提交/审核/驳回/下推/打印/反审核/作废）。
- 杠杆点：`DocListPage.vue` 是 8 个页面的共用壳，**改一个文件覆盖 8 个页面**；`ContractsView.vue:772` 再改一次即可。
- 改法：加 `type="selection"` + 表头批量条（批量提交 / 批量审核 / 批量导出 / 批量停用），批量动作必须逐条报错汇总（避免全成功全失败的黑箱）。

**P0-5 建立设计令牌并替换硬编码**

- 现状：`web/src/style.css` 11 行、0 令牌，21 个色值 / 12 种字号散落在 40+ 个 `<style scoped>`。
- 改法：在 `style.css` 定义最小可用令牌集并**同时覆盖 Element Plus 变量**，一次改动即全站生效：

```css
:root {
  /* 文字 */
  --ctms-text: #303133;
  --ctms-text-secondary: #606266;
  --ctms-text-muted: #7a7f87;   /* 替代 #909399 作正文级次要文字，对比度 ≥ 4.5:1 */
  --ctms-text-placeholder: #a8abb2;

  /* 功能色（文字用深色，底色用浅色） */
  --ctms-primary: #2f6fed;
  --ctms-danger-text: #c45656;
  --ctms-warning-text: #b88230;
  --ctms-success-text: #4e9a51;

  /* 字号（6 档，替换现有 12 种） */
  --ctms-fs-xs: 12px;    /* 表格内辅助 */
  --ctms-fs-sm: 13px;    /* 次要说明（替代 12.5px） */
  --ctms-fs-base: 14px;  /* 正文/表格 */
  --ctms-fs-md: 16px;    /* 区块标题 */
  --ctms-fs-lg: 20px;    /* KPI */
  --ctms-fs-xl: 28px;    /* 大屏 KPI */

  /* 间距（4 的倍数，替换现有 12/10/8/6/4 混用） */
  --ctms-gap-xs: 4px;
  --ctms-gap-sm: 8px;
  --ctms-gap: 12px;
  --ctms-gap-md: 16px;
  --ctms-radius: 4px;

  /* 全局：数值可比对 + 主题色声明 */
  color-scheme: light;
}
.el-table, .el-table td, .el-table th { font-variant-numeric: tabular-nums; }
```

**P0-6 区分「未登录」与「网络抖动」**

- 现状：`router/index.ts:311-316` 的 `fetchMe` 失败一律 `auth.setToken('')` 并跳登录页；`SettingsView.vue:99-101` 的 `Promise.all` 完全没有 `catch`。
- 后果：内网瞬时断网、后端 5xx、重启后端，都会把已登录用户**踢回登录页**，丢掉当前页与未保存的录入内容（与 P0-1 叠加成双重数据损失）。
- 改法：只在 HTTP 401 时清 token 并跳登录；网络类错误保留登录态，给出「网络异常，请重试」并允许原地重试。

### P1 —— 效率与专业度

**P1-1 筛选/分页/Tab 同步到 URL query**

- 现状：全项目 0 个页面读 `useRoute().query`，筛选条件全在内存 → 不可分享、不可深链、**浏览器回退直接离开页面**。
- 改法：至少覆盖 `ContractsView.vue:46-54` 与 `DocListPage.vue:117-126`：`router.replace({ query })` 写入 + `onMounted` 回填 + 监听 `route.query` 变化。
- 顺带修两个真实 bug：`ContractsView.vue:750` 的「重置」漏了 `include_deleted` 与 `page=1`；`ContractsView.vue:754` 仍在用 Element Plus 2.6+ 已弃用的 `el-checkbox label` 作值。

**P1-2 金额/数量列：右对齐 + `tabular-nums`**

- 现状：全站数值列无一处等宽数字，金额与数量无法纵向比对；合同台账把「金额 / 已付 / 比例」压成同级小字（`ContractsView.vue:808-819`，比例降到 12px `#909399`）。
- 改法：数值列统一 `align="right"` + 全局 `tabular-nums`（见 P0-5）；金额用 `--ctms-fs-base` 加深到 `--ctms-text`，让它在行内成为视觉第一层。

**P1-3 操作列收纳：9 个平铺按钮 → 1 主 + 2 次 + 「更多」**

- 现状：`DocListPage.vue:472` 操作列宽 320px 内最多 9 个同权重 link 按钮；`ContractsView.vue` 行内 4 个按钮 30×18px（实测 19 个过小点击目标）。
- 改法：保留 1 个高频动作（查看/编辑）+「更多」下拉收纳其余；所有图标按钮补 `aria-label`；点击目标提到 ≥32px 高。

**P1-4 补空态与错误态**

- 空态三种语言混用：`template #empty` 文本 / `el-empty` 插图 / `el-alert` 说明；而 `ContractsView.vue:772`、`UserView.vue:208`、`RoleView.vue:182`、`SystemView.vue:242` 主干表**完全没有空态**。
- 错误态缺失（比空态更严重）：`DocListPage.vue:196-200`（先开抽屉再取数，失败永久空白）、`ContractDetailDrawer.vue:53`（`loading` 在 `v-if` 之外，失败只剩空白）、`TreeMasterPage.vue:50`（`try/finally` 无 `catch` → 空树 + 未捕获 rejection）、`api.ts:45`（仅当 `detail` 是字符串才提示，500 静默）。
- 建议以 `PartyDraftView.vue:178` 为全站空态标准（它是全项目最好的写法），并为所有异步区块补「失败 + 重试」。

**P1-5 表单校验从 toast 迁到行内**

- 现状：行项校验用 `ElMessage.warning`（`ContractsView.vue:459-463`、`DocFormPage.vue:162-183`、`TakeForm.vue:187-201`），提示文案本身很好（「第 N 行：请选择物料档案」），但**错误不在字段旁、不聚焦首个错误**，长表单里提示一闪即逝。
- 改法：行项错误用 `el-table` 行高亮 + 单元格内红字；表头字段走 `el-form` 的 `rules` + `scrollToField`；保留现有中文文案（文案质量高，别改）。

**P1-6 窄屏与弹窗适配**

- 现状：全项目仅 1 处媒体查询；弹窗写死宽度 `ContractsView.vue:849(1080px)`、`:1015(760px)`、`:1040(720px)`、`:1130(640px)`；`:span` 全固定（`DashboardView.vue:101-110`、`DocFormPage.vue:321-351`）。
- 实测：1024 宽下无横向溢出（好），但主区被压到 804px，合同台账的甲方/乙方列被压成「华东机…」——**比出现滚动条更糟**。
- 改法：弹窗改 `width="min(1080px, 92vw)"`；卡片栅格加 `:xs="24" :sm="12" :md="6"`；表格给关键列设 `min-width` 并允许容器横向滚动。

**P1-7 修侧栏高亮丢失（长会话定位感）**

- 现状：`AppLayout.vue:16` 用 `activeMenu = route.path` 精确匹配菜单 index（`/purchase/orders`），而所有详情/编辑路由是 `/purchase/orders/:id`、`/purchase/orders/new`、`/purchase/orders/:id/edit`（`router/index.ts:116-129,137-150,159-172`）。
- 后果：**进入任何详情页或编辑页，侧栏高亮全部消失**——用户在长会话中持续失去「我在哪」。
- 改法：`activeMenu` 改为按 `route.matched` 或「最长前缀匹配菜单路径」计算。

**P1-8 补焦点可见性与键盘可达性**

- `TopBar.vue:70` 的 `outline: none` 抹掉了 Element Plus 已经提供的 `role="button" tabindex="0"` 焦点环 → 键盘用户完全看不到焦点位置（同文件也没有 `:hover` 反馈，全 `web/src` 对 `:hover` 命中为 0）。
- 改法：删除 `outline: none`，补 `.user:focus-visible { outline: 2px solid var(--ctms-primary); outline-offset: 2px; }`；按钮/链接补 `:hover`、`:active`；顺带为 `TopBar.vue:42`、`MenuTree.vue:15,21` 的装饰图标加 `aria-hidden="true"`，`LoginView.vue:62` 的错误段落加 `role="alert" aria-live="polite"`。

**P1-9 字典页（SettingsView）状态与防丢**

- `SettingsView.vue:117,137,160,178` 四张表没有 loading / 空态 / 错误态区分，加载中与「无数据」长得一样；`:42-43,83-88,150,186` 表内本地编辑 + 手动保存，切菜单即静默丢弃；`:145,183` 删除无确认（而 `:70` 删标签有确认，同类操作两套标准）。
- 改法：四张表加 `v-loading` + `#empty`；编辑态加脏检查（同 P0-1）；删除确认对齐 `:70` 的「影响面提示」写法（`usage_count` 提示是很棒的范式，应扩散）。

### P2 —— 一致性与工程化

## 五、Keep —— 明确不要破坏的东西

1. **配置驱动壳的边界划分**：把 12 个页面收敛成 5 个壳，是全项目最值钱的架构决定；一致性矩阵里的整齐项全部来自它。
2. **按权限点隐藏 + 后端硬校验的双层放行**：`DocListPage.vue:133-139,319-344`、`ContractsView.vue:10-11`，且 `canPush` 有「字段缺失时不隐藏」的详尽防线注释（`DocListPage.vue:334-342`）——体验层可退化、边界在后端，写法正确。
3. **数量精度跟随单位小数位**：`DocItemsTable.vue:58-65,146-154,172-182` + `TakeForm.vue:69-79`，录入端与校验端同源，避免「0.5 个」这类脏数据。
4. **行内精确中文错误提示**：「第 N 行：单位不支持小数」——直接告诉用户改哪一行，比通用 toast 有效得多（只需改呈现位置，文案别动）。
5. **三处真正有设计想法的实现**：合同框架树的展示层语义边界（`ContractsView.vue:56-99,845` 用 alert 显式说明）、盘点单账面冻结 + 差异高亮（`TakeForm.vue:81-115,405-406`）、库存重算校验 + 按流水修复（`BalanceView.vue:191-214`）。
